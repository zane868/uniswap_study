## 摘要

本规范定义**智能体商业协议（Agentic Commerce Protocol，ACP）**：以一个托管预算资金的**任务（job）**为核心，分为四个阶段（Open → Funded → Submitted → Terminal），且只有**评估方（evaluator）**能将任务标记为完成。客户为任务注资，服务提供方提交工作成果，评估方在成果提交后确认完成或拒绝任务。任务也可以在提交前、处于 Funded 状态时被评估方拒绝，在 Open 状态时被客户拒绝，或在到期后退款给客户。完成或拒绝任务时，可以附带证明**理由（reason）**，例如哈希，用于审计，并与信誉系统（如 [ERC-8004](https://eips.ethereum.org/EIPS/eip-8004)）结合使用。

## 动机

许多场景只需要一个简单流程：客户锁定资金，服务提供方提交成果，一名证明方（即评估方）确认完成后触发付款；或者客户拒绝任务、任务超时后退款。智能体商业协议只定义这些必要功能，使实现保持精简，便于与其他协议组合。如果不需要第三方证明，评估方也可以由客户担任，例如在创建任务时设置 `evaluator = client`。

## 规范

本文中的关键词“必须（MUST）”“不得（MUST NOT）”“必需（REQUIRED）”“必须（SHALL）”“不得（SHALL NOT）”“应当（SHOULD）”“不应当（SHOULD NOT）”“推荐（RECOMMENDED）”“不推荐（NOT RECOMMENDED）”“可以（MAY）”和“可选（OPTIONAL）”，应按照 RFC 2119 和 RFC 8174 的规定解释。

### 状态机

一个**任务**在任意时刻只能处于以下六种状态之一：

| 状态 | 含义 |
| --- | --- |
| **Open** | 已创建，但尚未设置预算或尚未注资。客户可以设置预算，然后注资或拒绝任务。 |
| **Funded** | 预算资金已托管。服务提供方可以提交成果，评估方可以拒绝任务。到达 `expiredAt` 后，任何人都可以触发退款。 |
| **Submitted** | 服务提供方已提交成果。只有评估方能确认完成或拒绝任务。到达 `expiredAt` 后，任何人都可以触发退款。 |
| **Completed** | 终态。托管资金支付给服务提供方，可扣除平台费用。 |
| **Rejected** | 终态。托管资金退还客户。 |
| **Expired** | 终态。与 Rejected 一样，托管资金退还客户。 |

允许的状态转换如下：

- **Open → Funded**：客户或服务提供方调用 `setBudget(jobId, amount)` 确定价格，随后客户调用 `fund(jobId, expectedBudget)`；合约从客户账户转入 `job.budget` 对应的资金进行托管。
- **Open → Rejected**：客户调用 `reject(jobId, reason?)`。
- **Funded → Submitted**：服务提供方调用 `submit(jobId, deliverable)`，表示工作已经完成，可以开始评估。
- **Funded → Rejected**：评估方调用 `reject(jobId, reason?)`；合约退款给客户。
- **Funded → Expired**：当 `block.timestamp >= job.expiredAt` 时，任何人（也包括客户）都可以调用 `claimRefund(jobId)`；合约将状态设为 Expired，并退款给客户。
- **Submitted → Completed**：评估方调用 `complete(jobId, reason?)`；合约向服务提供方支付托管资金，如有费用，则将费用支付给资金库。
- **Submitted → Rejected**：评估方调用 `reject(jobId, reason?)`；合约退款给客户。
- **Submitted → Expired**：当 `block.timestamp >= job.expiredAt` 时，任何人（也包括客户）都可以调用 `claimRefund(jobId)`；合约将状态设为 Expired，并退款给客户。

其他状态转换均无效。

### 角色

- **客户（Client）**：创建任务并提供描述。若创建时未指定服务提供方，可以通过 `setProvider(jobId, provider)` 设置。通过 `setBudget(jobId, amount)` 设置预算，通过 `fund(jobId, expectedBudget)` 注入托管资金。**只有在 Open 状态下**，客户才能以客户身份拒绝任务。任务进入 Rejected 或 Expired 状态后，客户收到退款。
- **服务提供方（Provider）**：在创建时指定，或稍后通过 `setProvider` 设置。可以调用 `setBudget(jobId, amount)` 报价或协商价格。完成工作后调用 `submit(jobId, deliverable)`，使任务从 Funded 进入 Submitted，交由评估方评估。任务完成后收款。不调用 `complete` 或 `reject`。
- **评估方（Evaluator）**：每个任务只有一个评估方地址，在创建时指定。任务处于 Submitted 状态时，**只有**评估方可以（MAY）调用 `complete(jobId, reason?)` 或 `reject(jobId, reason?)`。任务处于 Funded 状态、尚未提交成果时，评估方也可以（MAY）调用 `reject(jobId, reason?)`。评估方可以（MAY）是客户本人，例如 `evaluator = client`，这样无需第三方即可确认完成或拒绝任务；也可以（MAY）是**智能合约**，先执行任意检查，例如验证零知识证明或汇总链下信号，再决定是否调用任务的 `complete` 或 `reject`。

### 任务数据

每个任务必须（SHALL）至少包含：

- `client`、`provider`、`evaluator`：地址。**创建时 provider 可以（MAY）为零地址**，详见下文“延后设置服务提供方”。
- `description`：字符串，创建时设置，例如任务简述或范围说明的引用。
- `budget`：`uint256`。
- `expiredAt`：`uint256` 类型的时间戳。
- `status`：Open、Funded、Submitted、Completed、Rejected 或 Expired。
- `hook`：地址，可选（OPTIONAL）。用于在核心函数执行前后调用外部钩子合约，详见下文“钩子”。可以（MAY）设为 `address(0)`，表示不使用钩子。

支付必须（SHALL）使用单一 [ERC-20](https://eips.ethereum.org/EIPS/eip-20) 代币，可在合约级统一设置，也可在创建任务时指定。实现可以（MAY）允许每个任务使用不同代币；本规范只要求每个合约支持一种支付代币。

### 延后设置服务提供方

创建任务时，可以（MAY）向 `createJob` 传入 `provider = address(0)`，暂不指定服务提供方。此时客户必须（SHALL）在注资前调用 `setProvider(jobId, provider)` 设置服务提供方。这适用于先创建任务，再竞标或分配任务的流程。

- **setProvider(jobId, provider)**  
  只能由**客户**调用。任务不是 Open 状态、当前 `job.provider != address(0)`，或传入的 `provider == address(0)` 时，必须（SHALL）回滚。调用成功后，必须（SHALL）设置 `job.provider = provider` 并发出事件，例如 ProviderSet。实现可以（MAY）在未来允许操作员角色调用 setProvider；本规范的最小实现只要求允许客户调用。
- **fund(jobId, expectedBudget)**  
  如果 `job.provider == address(0)`，必须（SHALL）回滚，即注资前必须（MUST）设置服务提供方。如果 `job.budget != expectedBudget`，也必须（SHALL）回滚，以防止抢跑攻击。

### 核心函数

- **createJob(provider, evaluator, expiredAt, description, hook?)**  
  由客户调用。创建 Open 状态的任务，设置 `client = msg.sender`、`provider`、`evaluator`、`expiredAt`、`description`，以及可选的 `hook` 地址。如果 `evaluator` 为零地址，或 `expiredAt` 不是未来时间，必须（SHALL）回滚。**Provider 可以（MAY）为零地址**；此时客户必须（MUST）在 `fund` 之前调用 `setProvider`。`hook` 可以（MAY）设为 `address(0)`，表示不使用钩子。返回 `jobId`。
- **setProvider(jobId, provider, optParams?)**  
  由客户调用。任务不是 Open 状态、当前 `job.provider != address(0)`，或 `provider == address(0)` 时，必须（SHALL）回滚。必须（SHALL）设置 `job.provider = provider`。若配置了钩子，则将可选的 `optParams`（`bytes`）转发给钩子合约，详见“钩子”。
- **setBudget(jobId, amount, optParams?)**  
  由客户或服务提供方调用，设置 `job.budget = amount`。任务不是 Open 状态，或调用者既不是客户也不是服务提供方时，必须（SHALL）回滚。若配置了钩子，则转发 `optParams`。
- **fund(jobId, expectedBudget, optParams?)**  
  由客户调用。任务不是 Open 状态、调用者不是客户、预算为零、**尚未设置服务提供方**（`job.provider == address(0)`），或 `job.budget != expectedBudget` 时，必须（SHALL）回滚。最后一项用于防止抢跑攻击。必须（SHALL）将 `job.budget` 数量的支付代币从客户账户转入合约托管，并将状态设为 Funded。若配置了钩子，则转发 `optParams`。
- **submit(jobId, deliverable, optParams?)**  
  只能由服务提供方调用。任务不是 Funded 状态，或调用者不是该任务的服务提供方时，必须（SHALL）回滚。必须（SHALL）将状态设为 Submitted。`deliverable`（`bytes32`）用于引用提交的成果，例如链下交付物的哈希、IPFS CID 或证明承诺。必须（SHALL）发出包含 `deliverable` 的事件，例如 JobSubmitted。若配置了钩子，则转发 `optParams`。
- **complete(jobId, reason, optParams?)**  
  只能由评估方调用。任务不是 Submitted 状态，或调用者不是该任务的评估方时，必须（SHALL）回滚。必须（SHALL）将状态设为 Completed，并将托管资金支付给服务提供方；可以扣除平台费用，转入可配置的资金库。`reason` 为可选的证明信息，可以（MAY）是 `bytes32(0)` 或证明哈希。如提供 `reason`，必须（SHALL）将其包含在事件中。若配置了钩子，则转发 `optParams`。
- **reject(jobId, reason, optParams?)**  
  **Open 状态时由客户调用，Funded 或 Submitted 状态时由评估方调用**。任务不处于这三种状态，或调用者不是当前状态下有权拒绝任务的客户／评估方时，必须（SHALL）回滚。必须（SHALL）将状态设为 Rejected。若此前为 Funded 或 Submitted，必须（SHALL）将托管资金退还客户。`reason` 可选。如提供理由，必须（SHALL）发出包含 `reason` 及调用者（拒绝方）的事件。若配置了钩子，则转发 `optParams`。
- **claimRefund(jobId)**  
  任务处于 Funded 或 Submitted 状态且已到期（`block.timestamp >= expiredAt`）时可以调用。任务不处于上述状态，或尚未到期时，必须（SHALL）回滚。必须（SHALL）将全部托管资金退还客户，并将状态设为 Expired。实现可以（MAY）限制调用者，例如只允许客户调用，也可以允许任何人调用；本规范推荐（RECOMMENDS）允许任何人在到期后触发退款。

### 证明

- **complete(jobId, reason, optParams?)**：`reason` 是可选的证明承诺，例如链下证据的 `bytes32` 哈希。实现可以（MAY）接受 `string`，再在内部计算哈希。事件应当（SHOULD）包含 `reason`，便于索引和接入信誉系统。若配置了钩子，则转发 `optParams`。
- **reject(jobId, reason, optParams?)**：可选的 `reason` 用于审计，处理方式同上。若配置了钩子，则转发 `optParams`。

### 费用

实现可以（MAY）在任务完成时收取以基点计的**平台费用**，并支付至可配置的资金库。本规范不要求收费。如收取费用，必须（SHALL）只在任务完成时扣除，退款时不得扣除。

### 钩子（可选）

实现可以（MAY）为每个任务配置一个可选的**钩子合约**，用于扩展核心协议，而不必修改核心逻辑。钩子地址在创建任务时设置并保存在任务中；不使用钩子时设为 `address(0)`。忽略 `hook` 字段或始终将其设为 `address(0)` 的**无钩子核心实现**也完全符合本规范。参考实现中的 `AgenticCommerce` 采用这一最小模式，`AgenticCommerceHooked` 则是**扩展实现**，在相同生命周期上增加钩子回调。

钩子合约必须（SHALL）实现 `IACPHook` 接口，接口只有两个函数：

```solidity
interface IACPHook {
    function beforeAction(uint256 jobId, bytes4 selector, bytes calldata data) external;
    function afterAction(uint256 jobId, bytes4 selector, bytes calldata data) external;
}
```

`selector` 表示当前调用的核心函数，例如 `fund` 的函数选择器。`data` 包含编码为字节的函数参数，详见“数据编码”。钩子根据选择器执行不同逻辑：

```solidity
function beforeAction(uint256 jobId, bytes4 selector, bytes calldata data) external {
    if (selector == FUND_SELECTOR) {
        // 使用 data（optParams）执行自定义注资前逻辑
    } else if (selector == COMPLETE_SELECTOR) {
        // 使用 data（reason、optParams）执行自定义完成前逻辑
    }
}
```

如果任务配置了钩子，核心合约必须（SHALL）在每个支持钩子的函数执行前后，分别调用 `hook.beforeAction(...)` 和 `hook.afterAction(...)`：

| 核心函数 | 是否支持钩子 |
| --- | --- |
| `setProvider` | 是 |
| `setBudget` | 是 |
| `fund` | 是 |
| `submit` | 是 |
| `complete` | 是 |
| `reject` | 是 |
| `claimRefund` | **否**。这是无需许可的安全机制，不得（SHALL NOT）接入钩子。 |

#### 数据编码

传给钩子的 `data` 参数包含核心函数的参数，编码方式按选择器区分：

| 核心函数 | `data` 编码 |
| --- | --- |
| `setProvider` | `abi.encode(address provider, bytes optParams)` |
| `setBudget` | `abi.encode(uint256 amount, bytes optParams)` |
| `fund` | `optParams`（原始字节） |
| `submit` | `abi.encode(bytes32 deliverable, bytes optParams)` |
| `complete` | `abi.encode(bytes32 reason, bytes optParams)` |
| `reject` | `abi.encode(bytes32 reason, bytes optParams)` |

#### 钩子行为

- 每个支持钩子的核心函数都可带有 `optParams` 字段（`bytes`，可选）。核心合约通过 `data` 将其原样转发给钩子。不使用钩子的调用者可以（MAY）传入空字节。核心合约不得（SHALL NOT）解释 `optParams`，其内容只供钩子使用。
- **前置钩子**（`beforeAction`）在核心逻辑执行前调用。它可以（MAY）通过回滚阻止操作，例如执行自定义验证、白名单检查或前置条件检查。
- **后置钩子**（`afterAction`）在核心逻辑执行完成后调用，包括状态变更和代币转移。它可以（MAY）执行附加操作，例如发出事件、更新外部状态、触发通知，也可以通过回滚撤销整笔交易。
- 如果 `job.hook == address(0)`，核心合约必须（SHALL）跳过钩子调用，正常执行。

#### 钩子安全

- 钩子是由客户在创建任务时选择的**受信任合约**。恶意或存在缺陷的钩子可能使有效操作回滚，也可能在回调中执行任意逻辑。客户应当（SHOULD）审计钩子，或使用经过广泛验证的实现。
- **活性**：持续回滚的钩子可能阻断该任务所有支持钩子的操作，直到 `expiredAt`。这是有意的设计，因为钩子属于任务策略的一部分。到期后的 `claimRefund` 是保留的资金退出路径。该函数明确**不支持钩子**，以免退款被阻断。
- **原子性**：后置回调虽然在状态变更之后执行，但仍处于同一笔交易中。回调一旦回滚，整笔交易及核心状态变更都会回滚。这样可以实现原子的多步流程，例如托管注资与附加代币转账必须同时成功，否则一起回滚。
- 推荐（RECOMMENDED）在钩子上使用 `onlyACP` 修饰器，防止外部账户直接调用钩子函数。
- 任务创建后，钩子不应当（SHOULD NOT）再支持升级，否则其行为可能在任务执行期间发生变化。
- 实现可以（MAY）维护已审计钩子合约的白名单或注册表，降低客户风险。

#### 便捷基类（非规范性内容）

实现可以（MAY）提供 `BaseACPHook`，将通用的 `beforeAction`／`afterAction` 调用分派至具名虚函数，例如 `_preFund`、`_postComplete`，方便开发者只重写需要的函数。这不是标准的一部分，只有 `IACPHook` 属于规范性接口。

#### 应用示例

- 注资前验证，例如 KYC 检查或白名单限制。
- 完成后更新信誉，例如向 ERC-8004 写入证明。
- 自定义收费或分账。
- 原子化附加转账，例如资金转移钩子。
- 服务提供方竞标，例如竞标钩子。

#### 示例 1：资金转移钩子（两阶段托管）

**问题**：客户雇用智能体兑换、跨链转移或交换代币，例如 USDC → DAI。客户向服务提供方提供本金，由其获得输出代币。钩子必须确保服务提供方在任务完成前存入输出代币，并在完成后将其释放给指定买方。

**方案**：使用 `FundTransferHook`，在 `setBudget` 时记录转账承诺，在 `fund` 时将本金交给服务提供方，在 `submit` 时从服务提供方转入输出代币，最后在 `complete` 时将其释放给买方。

```
步骤 1：createJob
  客户 → createJob(provider, evaluator, expiredAt, desc, hook=FundTransferHook)
  任务创建，状态为 Open，钩子地址已记录。

步骤 2：setBudget
  客户 → setBudget(jobId, serviceFee, optParams=abi.encode(buyer, transferAmount))
    → hook.beforeAction：解码 optParams，将 {buyer, transferAmount} 存为承诺。
    → 核心合约：job.budget = serviceFee

步骤 3：fund
  客户授权：允许核心合约转移 serviceFee，允许钩子转移 transferAmount。
  客户 → fund(jobId, serviceFee, "")
    → hook.beforeAction：检查客户是否已向钩子授权 transferAmount，未授权则回滚。
    → 核心合约：将 serviceFee 转入托管，状态设为 Funded。
    → hook.afterAction：从客户转入 transferAmount，再交给服务提供方作为本金。

步骤 4：服务提供方使用本金获得输出代币

步骤 5：submit
  服务提供方向钩子授权 transferAmount 数量的输出代币。
  服务提供方 → submit(jobId, deliverable, "")
    → hook.beforeAction：从服务提供方转入 transferAmount，托管在钩子中。
    → 核心合约：状态设为 Submitted。

步骤 6：complete
  评估方 → complete(jobId, reason, "")
    → 核心合约：扣除平台费用后，将 serviceFee 支付给服务提供方。
    → hook.afterAction：将钩子中的 transferAmount 释放给买方。

资金取回：
  - reject：hook.afterAction 将已托管的代币退还服务提供方（如果已经存入）。
  - 到期：claimRefund 不经过钩子，将 serviceFee 退还客户。
    服务提供方调用钩子的 recoverTokens(jobId)，取回已存入的代币。
```

**关键性质**：（1）服务提供方未存入输出代币就无法提交成果。（2）只有评估方确认任务完成后，买方才能收到代币。（3）任务被拒绝或到期后，代币退还服务提供方。

#### 示例 2：竞标钩子

**问题**：客户希望为任务选择报价最低或最合适的智能体，但创建任务时还不知道应当指定谁。服务提供方应通过公开竞标选出，而不是事后由客户单方面决定。

**方案**：使用 `BiddingHook` 验证链下签名报价。服务提供方在链下签署报价承诺，客户收集报价、选出中标方，并通过 `setProvider` 提交中标报价的签名。钩子的 `beforeAction` 回调恢复签名者地址，检查其是否与选定的服务提供方一致，以证明对方确实承诺过这一价格。

整个流程无需直接调用钩子，所有交互都通过核心合约触发钩子回调。

```
步骤 1：createJob
  客户 → createJob(provider=0, evaluator, expiredAt, desc, hook=BiddingHook)
  任务创建，状态为 Open，provider = address(0)。

步骤 2：setBudget（通过钩子回调开启竞标）
  客户 → setBudget(jobId, maxBudget, optParams=abi.encode(biddingDeadline))
    → hook.beforeAction：记录该 jobId 的竞标截止时间。

步骤 3：在链下竞标
  服务提供方签署：keccak256(abi.encode(chainId, hookAddress, jobId, bidAmount))
  客户收集签名报价，选出中标方。
  核心合约不处理报价细节。

步骤 4：setProvider + setBudget（钩子验证中标报价签名，并约束预算）
  客户 → setProvider(jobId, winnerAddress, optParams=abi.encode(bidAmount, signature))
    → hook.beforeAction：检查竞标已截止，从签名恢复签名者地址，
      验证 signer == provider，记录承诺的 bidAmount。验证失败则回滚。
    → 核心合约：job.provider = winnerAddress
    → hook.afterAction：标记竞标结束，之后不能再次调用 setProvider。
  客户 → setBudget(jobId, bidAmount, "")
    → hook.beforeAction：要求 budget == committedAmount，不一致则回滚。

步骤 5：继续正常的任务流程
  客户 → fund(jobId, bidAmount, "")
  服务提供方 → submit(jobId, deliverable, "")
  评估方 → complete(jobId, reason, "")
```

**关键性质**：客户无法伪造服务提供方的报价承诺。钩子会验证选定的服务提供方确实签署过相应价格的报价。由于付款的是客户本人，客户有动力选择最低报价。

---

### 事件

实现应当（SHOULD）至少发出以下事件：

- **JobCreated**(jobId, client, provider, evaluator, expiredAt)
- **ProviderSet**(jobId, provider)：为创建时未指定服务提供方的任务设置服务提供方时发出。
- **BudgetSet**(jobId, amount)
- **JobFunded**(jobId, client, amount)
- **JobSubmitted**(jobId, provider, deliverable)：服务提供方提交成果供评估时发出。
- **JobCompleted**(jobId, evaluator, reason)
- **JobRejected**(jobId, rejector, reason)
- **JobExpired**(jobId)
- **PaymentReleased**(jobId, provider, amount)
- **Refunded**(jobId, client, amount)

## 设计理由

- **提交后由单一证明方决定结果**：进入 Submitted 状态后，只有评估方能确认完成或拒绝任务，客户不能单方面取回资金，保护服务提供方开始工作后的权益。设置 `evaluator = client` 可以满足不需要第三方的场景。
- **明确提交成果**：Submitted 状态向评估方、索引器和界面发出明确信号，表示服务提供方认为工作已完成，可以开始评估，从而区分“已注资、执行中”和“已交付”。
- **只保留必要功能**：证明使用 complete／reject 中可选的 `reason` 字段，无需额外的账本。
- **四个阶段**：Open、Funded、Submitted 和 Terminal（Completed、Rejected 或 Expired）足以表达“注资 → 工作 → 提交 → 评估或退款”的流程。
- **到期机制**：到达 `expiredAt` 后可以退款，客户无需等待任务被明确拒绝，就有办法取回资金。
- **用钩子扩展，而不是继承**：集成方可以通过可选钩子扩展验证、信誉、收费等功能，无需修改或继承核心合约。核心保持精简，复杂逻辑放在钩子中。
- **通用钩子接口**：`IACPHook` 只定义两个函数（`beforeAction`／`afterAction`），通过 selector 参数区分操作，而不为每项操作单独定义函数。核心协议新增支持钩子的函数时，只需增加选择器值，无需修改接口。

### 扩展（可选）

以下扩展均为可选（OPTIONAL），不改变核心协议，实现可以（MAY）独立采用。

#### 与信誉／证明系统互操作（ERC-8004）

智能体商业协议有意保持精简，不内置信誉系统。如需支持智能体之间的链上信誉和信任关系，推荐（RECOMMENDED）集成 [ERC-8004](https://eips.ethereum.org/EIPS/eip-8004)（Trustless Agents，无需预先信任的智能体）。

推荐（RECOMMENDED）采用以下模式：

- **根据任务结果生成信任信号**
  - 每个任务结果应当（SHOULD）映射为参与方的信任信号：
    - `Completed`：成功交付，为服务提供方生成正面信号，也可以为评估方生成正面信号。
    - `Rejected`：根据拒绝理由及拒绝方是客户还是评估方，生成负面或中性信号。
    - `Expired`：根据上层策略，对未评估的客户或未提交成果的服务提供方生成中性或轻微负面信号。
  - 任务进入终态时，实现可以（MAY）发出兼容 ERC-8004 的事件，或调用 ERC-8004 注册表。

- **评估方证明**
  - 调用 `complete(jobId, reason, optParams?)` 和 `reject(jobId, reason, optParams?)` 时，评估方可以（MAY）是合约，并应当（SHOULD）执行以下一项或两项操作：
    - 生成证明或结构化日志，作为反馈加入 ERC-8004 **信誉注册表**，例如“服务提供方成功完成任务”“任务因 X 理由被拒绝”。证明可以（MAY）引用任务、参与方和 `reason`，例如链下证据的哈希。
    - 向 ERC-8004 **验证注册表**提交证明，再由钩子或评估方合约读取，决定将任务标记为 `Completed` 还是 `Rejected`。
  - 可以（MAY）在 `complete`／`reject` 的 `afterAction` 钩子中调用 ERC-8004 注册表，使 ACP 核心合约无需处理注册表的具体细节。

- **通过钩子执行信誉策略**
  - 钩子可以（MAY）先查询 ERC-8004 数据，再决定是否允许某项操作，例如：
    - 阻止 `setProvider` 指定信誉低于门槛的服务提供方。
    - 对信誉较低的智能体要求更高预算或额外保障。
    - 根据信誉动态选择评估方。
  - 这类检查应放在执行策略的 `beforeAction` 钩子中，以便通过回滚阻止违反信誉策略的操作。

- **职责分离**
  - ACP 负责**支付和托管**，ERC-8004 负责**身份和信誉**。
  - 两者通过以下一种或两种方式互操作：
    - 发出 ERC-8004 索引器可以处理的事件。
    - 从钩子或评估方合约调用 ERC-8004 合约。

#### 元交易／代付服务中继（[ERC-2771](https://eips.ethereum.org/EIPS/eip-2771)）

为支持用户无需支付 Gas 的执行方式，即客户、服务提供方或评估方在链下签署操作意图，由**代付服务方（facilitator）**代为提交交易，实现应当（SHOULD）支持 [ERC-2771](https://eips.ethereum.org/EIPS/eip-2771)（原生元交易安全协议）。

**工作流程**：

1. 参与方（客户、服务提供方或评估方）在链下签署元交易，例如 `createJob`、`fund` 或 `submit`。
2. 代付服务方将已签名的载荷提交至**可信转发器（trusted forwarder）**合约。
3. 转发器验证签名，调用 ACP 合约，并在调用数据中附上原始签名者地址。
4. ACP 合约使用 `ERC2771Context` 提供的 `_msgSender()` 识别调用者，而不是使用 `msg.sender`。

**实现要求**：

- ACP 合约必须（SHALL）继承 `ERC2771Context` 或采用等效实现，并在所有客户、服务提供方和评估方权限检查中使用 `_msgSender()`。
- 所有角色检查，例如“调用者是否为客户”“调用者是否为服务提供方”，必须（SHALL）使用 `_msgSender()`，而不是 `msg.sender`。
- 可信转发器地址必须（SHALL）在部署时设置，且应当（SHOULD）不可更改。

```solidity
import {ERC2771Context} from "@openzeppelin/contracts/metatx/ERC2771Context.sol";

contract AgenticCommerce is ERC2771Context, ... {
    constructor(address trustedForwarder, ...)
        ERC2771Context(trustedForwarder) { ... }

    // 示例：fund() 使用 _msgSender()，而不是 msg.sender
    function fund(uint256 jobId, uint256 expectedBudget) external {
        Job storage job = jobs[jobId];
        if (_msgSender() != job.client) revert Unauthorized();
        if (job.budget != expectedBudget) revert BudgetMismatch();
        // ...
    }
}
```

**代币授权**：对于需要从用户账户转入代币的函数，例如 `fund`，签名者应当（SHOULD）使用 [ERC-2612](https://eips.ethereum.org/EIPS/eip-2612) 的 `permit`，通过签名授权代币支出。这样代付服务方就可以在一笔交易中调用 `permit` 和 `fund`，签名者无需另外发送链上授权交易。

**x402 兼容性**：该扩展可以兼容 x402 等基于 HTTP 的支付协议。AI 智能体在链下签署支付意图，由支付代付服务方处理链上执行。智能体只需持有私钥和代币，无需自行支付 Gas、管理 RPC 或处理特定链的逻辑。

## 参考实现

参考实现由两个合约组成：`IACPHook` 是供开发者实现的可选最小钩子接口；`AgenticCommerce` 是核心任务合约，提供资金托管和可选的钩子扩展点。

### IACPHook.sol

```solidity
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/utils/introspection/IERC165.sol";

interface IACPHook is IERC165 {
    function beforeAction(uint256 jobId, bytes4 selector, bytes calldata data) external;
    function afterAction(uint256 jobId, bytes4 selector, bytes calldata data) external;
}
```

### AgenticCommerce.sol

```solidity
pragma solidity ^0.8.28;

import "@openzeppelin/contracts-upgradeable/access/AccessControlUpgradeable.sol";
import "@openzeppelin/contracts-upgradeable/proxy/utils/UUPSUpgradeable.sol";
import "@openzeppelin/contracts-upgradeable/proxy/utils/Initializable.sol";
import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";
import "@openzeppelin/contracts/utils/ReentrancyGuardTransient.sol";
import "./IACPHook.sol";
import "@openzeppelin/contracts/utils/introspection/ERC165Checker.sol";

contract AgenticCommerce is Initializable, AccessControlUpgradeable, ReentrancyGuardTransient, UUPSUpgradeable {
    using SafeERC20 for IERC20;

    bytes32 public constant ADMIN_ROLE = keccak256("ADMIN_ROLE");

    enum JobStatus {
        Open,
        Funded,
        Submitted,
        Completed,
        Rejected,
        Expired
    }

    struct Job {
        uint256 id;
        address client;
        address provider;
        address evaluator;
        string description;
        uint256 budget;
        uint256 expiredAt;
        JobStatus status;
        address hook;
    }

    IERC20 public paymentToken;
    uint256 public platformFeeBP;
    address public platformTreasury;
    uint256 public evaluatorFeeBP;

    mapping(uint256 => Job) public jobs;
    uint256 public jobCounter;
    mapping(address => bool) public whitelistedHooks;
    mapping(uint256 jobId => bool hasBudget) public jobHasBudget;

    event JobCreated(
        uint256 indexed jobId, address indexed client, address indexed provider,
        address evaluator, uint256 expiredAt, address hook
    );
    event ProviderSet(uint256 indexed jobId, address indexed provider);
    event BudgetSet(uint256 indexed jobId, uint256 amount);
    event JobFunded(uint256 indexed jobId, address indexed client, uint256 amount);
    event JobSubmitted(uint256 indexed jobId, address indexed provider, bytes32 deliverable);
    event JobCompleted(uint256 indexed jobId, address indexed evaluator, bytes32 reason);
    event JobRejected(uint256 indexed jobId, address indexed rejector, bytes32 reason);
    event JobExpired(uint256 indexed jobId);
    event PaymentReleased(uint256 indexed jobId, address indexed provider, uint256 amount);
    event EvaluatorFeePaid(uint256 indexed jobId, address indexed evaluator, uint256 amount);
    event Refunded(uint256 indexed jobId, address indexed client, uint256 amount);
    event HookWhitelistUpdated(address indexed hook, bool status);

    error InvalidJob();
    error WrongStatus();
    error Unauthorized();
    error ZeroAddress();
    error ExpiryTooShort();
    error ZeroBudget();
    error ProviderNotSet();
    error FeesTooHigh();
    error HookNotWhitelisted();

    /// @custom:oz-upgrades-unsafe-allow constructor
    constructor() {
        _disableInitializers();
    }

    function initialize(address paymentToken_, address treasury_) public initializer {
        if (paymentToken_ == address(0) || treasury_ == address(0))
            revert ZeroAddress();

        __AccessControl_init();

        paymentToken = IERC20(paymentToken_);
        platformTreasury = treasury_;
        _grantRole(DEFAULT_ADMIN_ROLE, msg.sender);
        _grantRole(ADMIN_ROLE, msg.sender);
        whitelistedHooks[address(0)] = true;
    }

    function _authorizeUpgrade(address newImplementation) internal override onlyRole(DEFAULT_ADMIN_ROLE) {}

    // ──────────────────── 管理操作 ────────────────────

    function setPlatformFee(uint256 feeBP_, address treasury_) external onlyRole(ADMIN_ROLE) {
        if (treasury_ == address(0)) revert ZeroAddress();
        if (feeBP_ + evaluatorFeeBP > 10000) revert FeesTooHigh();
        platformFeeBP = feeBP_;
        platformTreasury = treasury_;
    }

    function setEvaluatorFee(uint256 feeBP_) external onlyRole(ADMIN_ROLE) {
        if (feeBP_ + platformFeeBP > 10000) revert FeesTooHigh();
        evaluatorFeeBP = feeBP_;
    }

    function setHookWhitelist(address hook, bool status) external onlyRole(ADMIN_ROLE) {
        if (hook == address(0)) revert ZeroAddress();
        whitelistedHooks[hook] = status;
        emit HookWhitelistUpdated(hook, status);
    }

    // ──────────────────── 钩子辅助函数 ────────────────────

    function _beforeHook(address hook, uint256 jobId, bytes4 selector, bytes memory data) internal {
        if (hook != address(0)) {
            IACPHook(hook).beforeAction(jobId, selector, data);
        }
    }

    function _afterHook(address hook, uint256 jobId, bytes4 selector, bytes memory data) internal {
        if (hook != address(0)) {
            IACPHook(hook).afterAction(jobId, selector, data);
        }
    }

    // ──────────────────── 任务生命周期 ────────────────────

    function createJob(
        address provider, address evaluator, uint256 expiredAt,
        string calldata description, address hook
    ) external nonReentrant returns (uint256) {
        if (evaluator == address(0)) revert ZeroAddress();
        if (expiredAt <= block.timestamp + 5 minutes) revert ExpiryTooShort();
        if (!whitelistedHooks[hook]) revert HookNotWhitelisted();
        if (hook != address(0)) {
            if (!ERC165Checker.supportsInterface(hook, type(IACPHook).interfaceId))
                revert InvalidJob();
        }

        uint256 jobId = ++jobCounter;
        jobs[jobId] = Job({
            id: jobId,
            client: msg.sender,
            provider: provider,
            evaluator: evaluator,
            description: description,
            budget: 0,
            expiredAt: expiredAt,
            status: JobStatus.Open,
            hook: hook
        });

        emit JobCreated(jobId, msg.sender, provider, evaluator, expiredAt, hook);
        _afterHook(hook, jobId, msg.sig, abi.encode(msg.sender, provider, evaluator));

        return jobId;
    }

    function setProvider(uint256 jobId, address provider_) external {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();
        if (job.status != JobStatus.Open) revert WrongStatus();
        if (msg.sender != job.client) revert Unauthorized();
        if (job.provider != address(0)) revert WrongStatus();
        if (provider_ == address(0)) revert ZeroAddress();
        job.provider = provider_;
        emit ProviderSet(jobId, provider_);
    }

    function setBudget(uint256 jobId, uint256 amount, bytes calldata optParams) external nonReentrant {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();
        if (job.status != JobStatus.Open) revert WrongStatus();
        if (msg.sender != job.provider) revert Unauthorized();

        bytes memory data = abi.encode(msg.sender, amount, optParams);
        _beforeHook(job.hook, jobId, msg.sig, data);

        job.budget = amount;
        emit BudgetSet(jobId, amount);
        jobHasBudget[jobId] = true;

        _afterHook(job.hook, jobId, msg.sig, data);
    }

    function fund(uint256 jobId, bytes calldata optParams) external nonReentrant {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();
        if (job.status != JobStatus.Open) revert WrongStatus();
        if (msg.sender != job.client) revert Unauthorized();
        if (job.provider == address(0)) revert ProviderNotSet();
        if (block.timestamp >= job.expiredAt) revert WrongStatus();

        bytes memory data = abi.encode(msg.sender, optParams);
        _beforeHook(job.hook, jobId, msg.sig, data);

        job.status = JobStatus.Funded;
        if (job.budget > 0) {
            paymentToken.safeTransferFrom(job.client, address(this), job.budget);
        }
        emit JobFunded(jobId, job.client, job.budget);

        _afterHook(job.hook, jobId, msg.sig, data);
    }

    function submit(uint256 jobId, bytes32 deliverable, bytes calldata optParams) external nonReentrant {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();
        if (
            job.status != JobStatus.Funded &&
            (job.status != JobStatus.Open || job.budget > 0)
        ) revert WrongStatus();
        if (msg.sender != job.provider) revert Unauthorized();

        bytes memory data = abi.encode(msg.sender, deliverable, optParams);
        _beforeHook(job.hook, jobId, msg.sig, data);

        job.status = JobStatus.Submitted;
        emit JobSubmitted(jobId, job.provider, deliverable);

        _afterHook(job.hook, jobId, msg.sig, data);
    }

    function complete(uint256 jobId, bytes32 reason, bytes calldata optParams) external nonReentrant {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();
        if (job.status != JobStatus.Submitted) revert WrongStatus();
        if (msg.sender != job.evaluator) revert Unauthorized();

        bytes memory data = abi.encode(msg.sender, reason, optParams);
        _beforeHook(job.hook, jobId, msg.sig, data);

        job.status = JobStatus.Completed;

        uint256 amount = job.budget;
        uint256 platformFee = (amount * platformFeeBP) / 10000;
        uint256 evalFee = (amount * evaluatorFeeBP) / 10000;
        uint256 net = amount - platformFee - evalFee;

        if (platformFee > 0) {
            paymentToken.safeTransfer(platformTreasury, platformFee);
        }
        if (evalFee > 0) {
            paymentToken.safeTransfer(job.evaluator, evalFee);
            emit EvaluatorFeePaid(jobId, job.evaluator, evalFee);
        }
        if (net > 0) {
            paymentToken.safeTransfer(job.provider, net);
        }

        emit JobCompleted(jobId, job.evaluator, reason);
        emit PaymentReleased(jobId, job.provider, net);

        _afterHook(job.hook, jobId, msg.sig, data);
    }

    function reject(uint256 jobId, bytes32 reason, bytes calldata optParams) external nonReentrant {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();

        if (job.status == JobStatus.Open) {
            if (msg.sender != job.client) revert Unauthorized();
        } else if (job.status == JobStatus.Funded || job.status == JobStatus.Submitted) {
            if (msg.sender != job.evaluator) revert Unauthorized();
        } else {
            revert WrongStatus();
        }

        bytes memory data = abi.encode(msg.sender, reason, optParams);
        _beforeHook(job.hook, jobId, msg.sig, data);

        JobStatus prev = job.status;
        job.status = JobStatus.Rejected;

        if ((prev == JobStatus.Funded || prev == JobStatus.Submitted) && job.budget > 0) {
            paymentToken.safeTransfer(job.client, job.budget);
            emit Refunded(jobId, job.client, job.budget);
        }

        emit JobRejected(jobId, msg.sender, reason);

        _afterHook(job.hook, jobId, msg.sig, data);
    }

    function claimRefund(uint256 jobId) external nonReentrant {
        Job storage job = jobs[jobId];
        if (job.id == 0) revert InvalidJob();
        if (job.status != JobStatus.Funded && job.status != JobStatus.Submitted)
            revert WrongStatus();
        if (block.timestamp < job.expiredAt) revert WrongStatus();

        job.status = JobStatus.Expired;

        if (job.budget > 0) {
            paymentToken.safeTransfer(job.client, job.budget);
            emit Refunded(jobId, job.client, job.budget);
        }

        emit JobExpired(jobId);
    }

    // ──────────────────── 查询 ────────────────────

    function getJob(uint256 jobId) external view returns (Job memory) {
        return jobs[jobId];
    }
}
```

## 安全注意事项

- 任务进入 Submitted 状态后，确认完成和拒绝任务都依赖评估方的判断；恶意评估方可能任意确认完成或拒绝任务。高价值任务应使用信誉机制（如 [ERC-8004](https://eips.ethereum.org/EIPS/eip-8004)）或质押机制。
- 注资后，只有评估方能拒绝任务，只有服务提供方能提交成果。客户不能单方面撤回资金，以保护已经开始工作的服务提供方。
- 不提供争议解决或仲裁机制；拒绝和到期都是最终结果。
- 每个合约只使用一种支付代币，可以减少攻击面；按任务指定代币属于扩展功能。
- **重入**：转移代币的函数必须（SHALL）受到保护，例如使用重入锁。
- **代币**：操作 [ERC-20](https://eips.ethereum.org/EIPS/eip-20) 时，使用 SafeERC-20 或等效方案。
- **评估方**：必须（MUST）在创建时指定。如果由客户确认完成，则传入 `evaluator = client`。
- **钩子 Gas 限制**：对于支持钩子的实现，应当（SHOULD）限制钩子调用的 Gas，例如使用 `call{gas: HOOK_GAS_LIMIT}(...)`，以限制执行成本，防止钩子消耗过多 Gas。不同链的 Gas 成本不同，具体上限由实现决定。
- 钩子合约由客户提供，并受客户信任。实现不得（MUST NOT）允许钩子直接修改核心托管状态。`claimRefund` 有意不支持钩子，确保恶意钩子无法阻止到期退款。
- 使用**高级钩子**的任务，例如额外托管代币的两阶段托管或资金转移钩子，通常比不使用钩子的普通任务具有**更多可能回滚的执行路径，与外部逻辑的耦合也更紧密**。这类钩子应当（SHOULD）仅供理解并接受这一取舍的智能体和用户使用。对大多数简单任务，推荐（RECOMMENDED）不使用钩子，或仅使用执行策略检查的钩子。
