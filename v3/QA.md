# Uniswap V3 学习问答

## 0. 什么叫集中流动性?

把有限的资金, 集中用于自己选定的价格范围

## 1. 集中流动性的优势是什么?

结论: 相较于 V2, V3 能将相同资金集中在指定价格区间内, 提供更深的流动性, 从而提高资金利用效率

### 示例

现在有 10 ETH, 1000 USDT 放入资金池

### V2

**上涨的场景**

假如: 1 ETH = 144 USDT

```text
因为: 10 × 1000 = 10000, 1 ETH = 1000 / 10 = 100
故: xy = 10000, y / x = 144, x ≈ 8.3333, y = 1200
```

上涨过程中实际流动的 ETH 减少 1.6667, USDT 增加了 200

**下跌的场景**

假如: 1 ETH = 64 USDT

```text
因为: 10 × 1000 = 10000, 1 ETH = 1000 / 10 = 100
故: xy = 10000, y / x = 64, x ≈ 12.5, y = 800
```

下跌过程中实际流动的 ETH 增加了 2.5, USDT 少了 200

这个现象得出: 整个上涨和下跌, ETH 只有 3 个在流动, USDT 只有 200 个在流动, 其余的都浪费了

### V3

基于 V2 的场景, 要获得 V2 一样的收益, 只需要准备 1.666 个 ETH, 200 USDT, 理论上来说就能获得 V2 一样的收益

V3 在当前价格为 100, 做市区间为 64-144 时, 只需约 1.6667 ETH 和 200 USDT, 就能提供与 V2 池相同交易深度

同样本金下, V3 可以提供更深的区间内流动性

## 2. 集中流动性在合约层面大致是如何实现的?

合约把每个 LP 的资金绑定到一个价格区间, 交易时只使用当前价格所在区间内的流动性, 跨过边界时, 再切换参与交易的流动性

### 1. 用 Position 记录个人仓位

用所有者地址 + tickLower + tickUpper 来记录

```text
仓位 A: [Tick 60, 180), L = 100
仓位 B: [Tick 120, 240), L = 200
```

### 2. 用 Tick 记录边界上的流动性变化

接前面的数据示例:

```text
Tick 60:  L + 100, A 进入
Tick 120: L + 200, B 进入
Tick 180: L - 100, A 退出
Tick 240: L - 200, B 退出
```

如果两个人选择了同一个池子, 相同的 Tick 范围, 他们的个人仓位分开记账, 收益按各自的 L 分配, 流动性记在 tick 上面, tick 是一个池子共享的

创建池子的时候, 根据传入的平方根价格, 计算当前价格对应的 Tick 编号

### 3. 池子维护当前有效流动性 liquidity

添加, 移除仓位时, 只有当前 Tick 位于 `[tickLower, tickUpper)` 内, 才同步调整池子的 liquidity

### 4. 交易按边界分段执行

假设当前 1 ETH = 2000 USDT, 需要卖出 3 ETH 换 USDT

```text
A: 1500-2500 USDT/ETH, 流动性: 1000
B: 1800-2200 USDT/ETH, 流动性: 1000
```

卖出 ETH, 会让池子里的 ETH 价格下降, 因此这次交易从 2000 往下走

**第一段: 价格从 2000 降到 1800**

这段 A, B 都参与:

- 消耗 ETH: 约 2.4191 ETH
- 输出 USDT: 约 4589.91 USDT
- 价格降到: 1800 USDT/ETH

B 只在 1800-2200 内做市, 价格继续跌到 1800 以下, 它就不再参与

**第二段: 用剩余 0.5809 ETH 继续兑换**

- 消耗剩余 ETH: 约 0.5809 ETH
- 输出 USDT: 约 1020.48 USDT
- 最终价格: 约 1714.45 USDT/ETH

1800 以上有 A, B 两份流动性, 1800 以下只有 A

合约必须先算到 1800, 减掉 B 的 L, 再计算剩余 ETH 能换多少 USDT, 这是分段场景

## 3. tick 和价格之间是什么关系?

tick 是价格刻度的编号, 主要用来标记流动性范围的上下边界; 刻度按固定比例排列, 所以同一套规则能适应不同价位的代币

### 一些基础知识的理解

1. 基础刻度是 1.0001, 写死在合约里面的
2. 基础刻度不代表绝对值, 是用来表示相对值, 如果当前刻度是 1.0001 代表上涨 0.01%, 不区分币种和额度
3. tickSpacing 代表每隔多少个基础刻度允许设置仓位边界, 具体刻度规则在 UniswapV3Factory 里面指定, 创建池子的时候可以选择哪一个刻度和对应的手续费

```solidity
feeAmountTickSpacing[500] = 10;     // 0.05% -> 间隔 10, 这里的 0.05% 代表手续费
feeAmountTickSpacing[3000] = 60;    // 0.3%  -> 间隔 60
feeAmountTickSpacing[10000] = 200;  // 1%    -> 间隔 200
```

### tick 和价格之间的关系推演

按照 1 ETH = 10000 USDT 来推演举例, 使用 10 tick 作为间隔, 目标是想控制在 0.05% 的波动范围内, 最小单位: ETH = 10^18, USDT = 10^16

**理想情况**

```text
最低: 10000 × (1 - 0.05%) = 9995 USDT
最高: 10000 × (1 + 0.05%) = 10005 USDT
```

**实际情况**

仓位边界需要对齐, 不能直接精确设置成这两个价格

已知:

```text
增加 1 Tick:  +0.01%, 10001 USDT
增加 10 Tick: 约 +0.100045%, 约 10010.0045 USDT
```

**为什么 10 tick 是 0.100045%?**

每增加 1 Tick, 价格都在"上一步价格"基础上乘以 1.0001, 不是一直按初始价格加

```text
第 1 Tick: 10000 × 1.0001 = 10001
第 2 Tick: 10001 × 1.0001 = 10002.0001
第 3 Tick: 10002.0001 × 1.0001 = 10003.00030001
...
第 10 Tick: 约 10010.0045012

最终:
(10010.0045012 - 10000) ÷ 10000 × 100% ≈ 0.100045%
```

在 0.05% 这个波动范围内的价格测算出四个价格:

| 合法 Tick | 价格(约) | 相对 10000 的变化 |
| ---: | ---: | ---: |
| -184230 | 9986.0281 | -0.139719% |
| -184220 | 9996.0186 | -0.039814% |
| -184210 | 10006.0191 | +0.060191% |
| -184200 | 10016.0297 | +0.160297% |

所以波动都严格不超过 0.05%, 这个池子的合法刻度无法满足, 只能使用刻度规格下计算的价格

tick 的值 -184230 的意义:

```text
1 ETH = 1.0001^(-184230) × 10^18 ÷ 10^6 ≈ 9986.03 USDT
```
