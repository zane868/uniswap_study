# Uniswap V3学习问答
## 1. 什么叫集中流动性?
把有限的资金, 集中用于自己选定的价格范围
## 2. 集中流动性的优势是什么?
结论: 相较于V2, V3能将相同资金集中在指定价格区间内, 提供更深的流动性, 从而提高资金利用效率
### 示例
现在有10ETH, 1000 USDT放入资金池
### V2
**上涨的场景**
假如: 1ETH = 144USDT
```text
因为: 10 × 1000 = 10000, 1ETH = 1000 / 10 = 100
故: xy = 10000, y / x = 144, x ≈ 8.3333, y = 1200
```
上涨过程中实际流动的ETH减少1.6667, USDT增加了200
**下跌的场景**
假如: 1ETH = 64USDT
```text
因为: 10 × 1000 = 10000, 1ETH = 1000 / 10 = 100
故: xy = 10000, y / x = 64, x ≈ 12.5, y = 800
```
下跌过程中实际流动的ETH增加了2.5, USDT少了200
这个现象得出: 整个上涨和下跌, ETH只有3个在流动, USDT只有200个在流动, 其余的都浪费了
### V3
基于V2的场景, 要获得V2一样的收益, 只需要准备1.666个ETH, 200USDT, 理论上来说就能获得V2一样的收益
V3在当前价格为100, 做市区间为64-144时, 只需约1.6667 ETH和200USDT, 就能提供与V2池相同交易深度
同样本金下, V3可以提供更深的区间内流动性
## 3. 集中流动性在合约层面大致是如何实现的?
合约把每个LP的资金绑定到一个价格区间, 交易时只使用当前价格所在区间内的流动性, 跨过边界时, 再切换参与交易的流动性
整体可以理解为建仓、记录流动性、兑换、手续费
### 建仓
- 用Position记录个人仓位
- 用所有者地址 + tickLower + tickUpper来记录
```text
仓位A: [Tick 60, 180), L = 100
仓位B: [Tick 120, 240), L = 200
```
### 流动性变化
- 用Tick记录边界上的流动性变化
接前面的数据示例:
```text
Tick 60:  L + 100, A进入
Tick 120: L + 200, B进入
Tick 180: L - 100, A退出
Tick 240: L - 200, B退出
```
如果两个人选择了同一个池子, 相同的Tick范围, 他们的个人仓位分开记账, 收益按各自的L分配, 流动性记在tick上面, tick是一个池子共享的
创建池子的时候, 根据传入的平方根价格, 计算当前价格对应的Tick编号
- 池子维护当前有效流动性liquidity
添加, 移除仓位时, 只有当前Tick位于 `[tickLower, tickUpper)` 内, 才同步调整池子的liquidity
### 兑换
- 交易按边界分段执行
假设当前1ETH = 2000USDT, 需要卖出3 ETH换USDT
```text
A: 1500-2500USDT/ETH, 流动性: 1000
B: 1800-2200USDT/ETH, 流动性: 1000
```
卖出ETH, 会让池子里的ETH价格下降, 因此这次交易从2000往下走
**第一段: 价格从2000降到1800**
这段A, B都参与:
- 消耗ETH: 约2.4191ETH
- 输出USDT: 约4589.91USDT
- 价格降到: 1800USDT/ETH
B只在1800-2200内做市, 价格继续跌到1800以下, 它就不再参与
**第二段: 用剩余0.5809 ETH继续兑换**
- 消耗剩余ETH: 约0.5809ETH
- 输出USDT: 约1020.48USDT
- 最终价格: 约1714.45USDT/ETH
1800以上有A, B两份流动性, 1800以下只有A
合约必须先算到1800, 减掉B的L, 再计算剩余ETH能换多少USDT, 这是分段场景
### 手续费
- 先累计，之后按仓位结算
- 在移除流动性之前可以直接提前
每笔交易后，合约不立即给所有LP转账，而是累计
token0、token1分别记账，LP操作仓位时再更新应得金额，随后领取。
## 4. tick和价格之间是什么关系?
tick是价格的“刻度编号”,刻度按固定比例排列, 用同一套规则能适应不同价位的代币
价格是这个编号对应的兑换比例。
### 一些基础知识的理解
1. 基础刻度是1.0001, 写死在合约里面的, tick用来作为1.0001指数的存在,p=10001^tick
2. tick编号能确定一个价格点，两个Tick的差，才表示相对价格变化
3. tickSpacing代表每隔多少个基础刻度允许设置仓位边界, 具体刻度规则在UniswapV3Factory里面指定, 创建池子的时候可以选择哪一个刻度和对应的手续费
### tick和价格之间的关系推演
按照1ETH=10000USDT (USDT/ETH) 来推演举例, 使用10tick作为间隔, 目标是想控制在0.05%的波动范围内,
最小单位: ETH = 10^18, USDT = 10^16
**理想情况**
```text
最低: 10000 × (1 - 0.05%) = 9995USDT
最高: 10000 × (1 + 0.05%) = 10005USDT
```
**实际情况**
仓位边界需要对齐, 不能直接精确设置成这两个价格
已知:
```text
增加1Tick:  +0.01%, 10001USDT
增加10Tick: 约 +0.100045%, 约10010.0045USDT
```
**为什么10 tick是0.100045%?**
每增加1Tick, 价格都在"上一步价格"基础上乘以1.0001, 不是一直按初始价格加
```text
第1Tick: 10000 × 1.0001 = 10001
第2Tick: 10001 × 1.0001 = 10002.0001
第3Tick: 10002.0001 × 1.0001 = 10003.00030001
...
第10Tick: 约10010.0045012
最终:
(10010.0045012 - 10000) ÷ 10000 × 100% ≈ 0.100045%
```
在0.05%这个波动范围的价格测算出四个最近价格:
| 合法Tick | 价格(约) | 相对10000的变化 |
| ---: | ---: | ---: |
| -184230 | 9986.0281 | -0.139719% |
| -184220 | 9996.0186 | -0.039814% |
| -184210 | 10006.0191 | +0.060191% |
| -184200 | 10016.0297 | +0.160297% |
波动都严格不超过0.05%, 这个池子的合法刻度无法满足, 只能使用刻度规格下计算的价格
### 三种操作情况
- 区间做市: 例如9986.0281 - 10016.0297进行做市，这里就需要按比例投入，投入10000USDT同时需要投入1.1455ETH
- 单边上限: 想高价格卖出ETH 10006.0191-10016.0297进行做市, 这里只需要投入ETH即可
- 单边下限: 想低价格买入ETH 9986.0281-9996.0186进行做市, 这里只需要投入USDT即
### tick使用
```text
1ETH = 1.0001^(-184230) × 10^18 ÷ 10^6 ≈ 9986.03USDT
```
## 5. 为什么V3需要tick?
集中流动性允许每个人选择不同的价格范围，tick为价格边界提供统一编号。当价格跨过某个仓位的边界时，程序就知道该让这笔流动性加入或退出，并记录手续费。
## 6. tickspacing和手续费费率之间有什么关系?
手续费决定“兑换收多少钱”，tickspacing决定“价格边界能选多细”。
V3在工厂合约中，把费率档位与tickspacing绑定。例如最初的三个档位：
```solidity
feeAmountTickSpacing[500] = 10;     // 0.05% -> 间隔10, 这里的0.05%代表手续费
feeAmountTickSpacing[3000] = 60;    // 0.3%  -> 间隔60
feeAmountTickSpacing[10000] = 200;  // 1%    -> 间隔200
```
## 7. 为什么不同费率池会对应不同的tick spacing?
主要是在价格范围的精细程度与链上计算成本之间做取舍。
- 低波动的交易对：价格可能长期只在很小的范围内变化，细刻度能让LP把资金集中到更准确的位置。这类交易对通常也适合较低手续费。
- 高波动的交易对：LP通常需要更高的手续费补偿风险。搭配较粗的刻度，可以限制边界的密集程度，减少交易中可能需要跨越和处理的边界数量。
ps: tickspacing不限制价格范围,限制的是精细度,spacing为10的时候，价格范围可以是 [-1000,+1000]，不过这里就隔了上万个tick,整体的计算成本就相对高，
